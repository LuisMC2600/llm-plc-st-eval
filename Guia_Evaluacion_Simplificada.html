Guía simplificada de evaluación

Tesis «LLM como Asistentes de Programación PLC en la Academia». Resume, caso por caso, cómo se califica cada tarea con las fichas de diagnóstico (C1, C5, C6, C2) y con la rúbrica de 5 criterios (25 tareas de código). Se basa en la clave, el enunciado y el protocolo del harness. No contiene calificaciones de ninguna respuesta.

0. ¿El método fue válido? Lista de verificación

Esta guía permite comprobar que los criterios se aplicaron bien, pero no que la evaluación haya sido independiente. Esto último depende de cómo se trabajó. Para poder reportarla como evaluación humana a ciegas deben cumplirse estos puntos:

1. Fichas de diagnóstico (C1, C5, C6)

Procedimiento común. Leer la clave (E1–E4) y después la respuesta completa. Para cada error de la clave:
  • Detectado = S si la respuesta señala el mismo defecto concreto, aunque use otras palabras o lo ubique en otra línea. Una mención vaga («revisar los temporizadores») no cuenta. Si el ítem tiene dos partes, basta con una (anotar cuál faltó).
  • Corrección válida = S si la corrección propuesta lo resolvería de verdad. Se deja vacía si el error no fue detectado.
  • Hallazgos adicionales: defectos reales que no están en la clave. Se cuentan una vez cada uno.
  • Errores inventados: lo que la respuesta presenta como error y no lo es. Se cuentan una vez cada uno.

3. Rúbrica de 5 criterios (25 tareas)

Orden recomendado para cada respuesta:
  1. Mirar el resultado de CODESYS (celda azul).
  2. Si no compila: IEC = 0 y Funcional = 0 (ya vienen fijados); puntuar coherencia, claridad y mantenibilidad leyendo el código.
  3. Si pasa todo el harness: Funcional = 3 (fijo); puntuar IEC (1–3) y los otros tres criterios.
  4. Si compila y falla pasos: Funcional 0–2 según qué pasos fallan (protocolo en el HTML de la tarea). 0 = falla el caso nominal; 1 = el nominal funciona y fallan casos límite; 2 = solo fallos menores sin riesgo.
  5. Si compila, pero no se pudo simular (interfaz no conforme): Funcional 0–2 leyendo el código, nunca 3.

Decisiones que deben acordarse antes y aplicarse igual en todas las tareas: (a) IEC de las respuestas con interfaz no conforme (¿1 o 2?); (b) si un defecto que el harness no detecta baja la coherencia; (c) si un literal que impone el propio enunciado (T#5S, 12…) penaliza la mantenibilidad; (d) en B3/C7, pin R estándar frente a RESET de CODESYS.

4. Revisión final de cada ficha

  • Todas las filas en «Completa».
  • Elegir dos respuestas con el mismo defecto y comprobar que tienen la misma nota.
  • Comprobar que las observaciones o justificaciones citan algo concreto del texto o del código.
  • Guardar la ficha con el nombre del evaluador y la fecha, y no editarla después de enviarla.
